# ADR-0009: Own SEO audits in one portable evidence workflow

- Status: accepted
- Date: 2026-11-02
- Owner: Project maintainer and implementing agent within task authority
- Evidence: User request to reference AgriciDaniel/claude-seo when introducing or updating workflows; [scope and design](https://github.com/WilsonLe/agentic-workflows/issues/80); routine implementation/design authority under Standard Development Workflow and ADR-0001
- Supersedes: none
- Superseded by: none

## Context

The bundle has campaign, ERPNext website, engineering and research owners but no
site-diagnosis owner. The separate [Product Growth proposal](https://github.com/WilsonLe/agentic-workflows/pull/78)
owns content acquisition and learning. Its reserved ADR-0008 remains in that
unmerged lane, so this decision uses ADR-0009. Technical indexing/schema/template
diagnosis has distinct evidence and recheck needs from audience/channel selection
or live account operations.

Claude SEO supplies useful conditional audit methods. Importing its whole
multi-skill/agent suite would duplicate routing and account/media responsibilities,
require a new runtime and bring universal scores, provider integrations and
tool-specific commands into a portable instruction bundle.

## Decision

One portable `seo-audit` skill owns site/page diagnosis, evidence-linked findings,
dependency-ordered remediation and recheck handoff in the existing bundle.
Conditional references cover technical/schema, content/AI search, site types and
measurement. A Markdown template is a fallback for consuming-project records,
not a new persisted schema, crawler, provider client or monitoring service.

Selectively adapt the pinned upstream methods with the MIT notice and documented
modifications. Use supported host/project tools or authorized exports. Missing
rendering, index, field or business evidence leaves those checks unassessed.
Eligibility, direct observations and business outcomes remain separate; no
universal score or threshold certifies ranking, citations or growth.

Restaurant Marketing retains campaign truth, economics and approval ownership.
ERPNext retains account operations and publication. When Product Growth is
available, it consumes content opportunities and outcome hypotheses; SEO Audit
retains site findings and technical rechecks. Engineering implementation and
external actions use their existing delivery and authority contracts.

The user implementation request and existing workflow policy authorize this
routine design on 2026-11-02. Accepted records the chosen owner; it does not
assert merge, installation, agent adherence or SEO outcomes.

## Alternatives

Extending restaurant campaigns or ERPNext operations to own general SEO would
couple diagnosis to one business/account type. Putting every audit into Product
Growth would burden channel/content experiments with indexing/rendering contracts.
Importing the upstream router and many agents would create overlapping owners
and harness dependencies. A new crawler/provider abstraction or audit database
has no demonstrated requirement for this instruction-level adoption.

## Consequences

The existing catalog and generator distribute the owner, references, template and
notice to Codex, Claude Code and OpenCode. Existing restaurant/ERPNext entry points
discover it as an available companion. No paid integration, provider credential,
automatic delegation or hook is introduced. Package checks establish distribution
and local reference integrity; actual inspection behavior and search/business
outcomes require separate task-specific evidence.

## Revisit

Extend this owner first when observed audits expose a missing method. Consider a
deterministic helper only for a repeated concrete operation with a validated
input/output, failure and authority contract that existing tools cannot satisfy.
Split ownership only when independent consumers demonstrate distinct lifecycle
and evidence needs. Reconcile the reserved ADR ID if concurrent proposals change
before merge, preserving accepted published decision history.
