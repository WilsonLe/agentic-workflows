# Humanizer onboarding

Use this guide when a user asks to set up, onboard, or get started with Humanizer.

## What to collect

Ask the user for:

- the text or file to edit;
- whether they want a rewrite, an AI-pattern audit, or voice matching;
- the purpose, audience, and desired register;
- facts, commitments, quotations, citations, formatting, or terminology that must not change;
- an optional writing sample when voice matching matters.

No account, credential, or external runtime is required.

## First-run workflow

1. Confirm the requested editing mode and the non-negotiable content.
2. Explain that Humanizer edits style, not truth, and does not promise AI-detector evasion.
3. For onboarding, use a short user-provided sample unless the user explicitly asks to process the complete document.
4. Return the edited sample first. Briefly identify any factual or tone decision that needs confirmation.
5. Ask whether the user wants the same treatment applied to the remaining text.

## Ready state

The workflow is ready when the source text, audience, target voice, and preserved facts are clear.

## Suggested first prompt

> Onboard me to Humanizer. Audit this short sample, rewrite it naturally without changing its meaning, and tell me what you need before applying the same voice to the full document.
